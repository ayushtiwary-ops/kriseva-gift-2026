## 4. Commit hygiene rules for the sprint

1. Commit every 20 to 30 minutes. A history with six commits looks like six copy-pastes. A history with sixty commits looks like a build.
2. Message format: `M<milestone>: <what changed> [by <human>]`. The named human is whoever reviewed it, and that human is the commit author.
3. Tag each milestone as it lands: `M1` through `M6`. Tags make the history readable at a glance during the audit.
4. Push often. Local-only work dies with a laptop.
5. Never commit credentials, access keys or `.env` contents. Add the ignore rules in the scaffold commit, before any AWS work starts.
6. No force-push, no rebase, no history rewriting, at any point, for any reason. A clean-looking history matters far less than an honest one, and rewriting is exactly what an auditor looks for.
7. If an agent produces something we do not fully understand, it does not get committed until a human can explain it. That rule is also our answer to the AI-built-code question.

If any of those look wrong, do not fix them by rewriting history. Explain them. A gap between 02:00 and 04:30 is a nap, and saying so is a better answer than a fabricated commit.
